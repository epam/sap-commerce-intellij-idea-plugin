Reports a property that SAP Commerce Cloud injects per environment being declared in an extension's project.properties.

A project.properties file is part of every build, and every build runs on every environment, so a database URL or a storage account written there hard-codes one environment into all of them. The value SAP Commerce Cloud injects at deployment time wins regardless, which makes the declaration misleading to read — and, for credentials such as db.password, a secret committed to the repository.

local.properties is where these belong: it describes the developer's own machine and takes no part in a cloud build.

Reported for the properties SAP documents as set by automation, among them:

  • db.url, db.driver, db.username, db.password
  • media.default.storage.strategy and the media.globalSettings.cloudAzureBlobStorageStrategy.* family
  • azure.hotfolder.storage.account.*, initialpassword.admin
  • everything under modelt., businessmetrics. and ccv2.services.

The quick fix moves the declaration to local.properties, replacing an existing declaration of the same key rather than duplicating it.
