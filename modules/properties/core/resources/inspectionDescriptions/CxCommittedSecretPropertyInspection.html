Reports a secret written into project.properties.

A project.properties file is committed, shipped in every build and readable by everyone with access to the repository. A password, token or API key written there is not configuration — it is a disclosure. Deleting the line afterwards does not undo it: the value stays in the repository history, so the secret has to be rotated, not just removed.

Keys are recognised by their last segment — password, secret, token, apiKey, accessKey, privateKey, credentials, connectionString and a few spellings of each. Ambiguous words are deliberately left out: a bare key is as often an identifier or a file name as it is a credential.

A declaration is not reported when:

  • the value is empty — the key is documentation, nothing more;
  • the value is entirely a ${...} placeholder — it has already been externalised;
  • the value is an obvious stand-in such as changeme, TODO or <your key here>.

local.properties is not inspected. It is where the other property inspections send these values, and saying both "put it here" and "do not put it here" would be no guidance at all. Keys that SAP Commerce Cloud already documents as managed — db.password, initialpassword.admin — are left to the inspection which owns them, so one line is never reported twice for the same reason.

Quick fixes move the declaration to local.properties, or clear the value while keeping the key.
